# MediAI — Agentic AI Platform for Breast Cancer Diagnosis

![Python](https://img.shields.io/badge/python-3.12-blue)
![FastAPI](https://img.shields.io/badge/FastAPI-0.115-green)
![React](https://img.shields.io/badge/React-18-61DAFB)

![Docker](https://img.shields.io/badge/Docker-ready-2496ED)

MediAI is a modular multi-agent decision-support platform for breast cancer diagnosis from mammograms. It combines fine-tuned computer vision models, a retrieval-augmented generation (RAG) pipeline over medical guidelines, and a large language model (LLM) to produce structured, interpretable clinical reports.

The entire pipeline is orchestrated with **LangGraph** and exposed through a **FastAPI** REST/WebSocket backend, with an intuitive **React** frontend featuring real-time progress tracking, annotated images, a PDF export, and a clinical chatbot.

## Features

- **Automatic lesion detection** using a fine-tuned YOLO11m model.
- **Elliptical morphological masking** for realistic metric extraction (area, perimeter, circularity).
- **Lesion classification** (Normal / Benign / Malignant) using a fine-tuned Swin Transformer.
- **BI-RADS automatic assignment** based on malignancy probability and ACR guidelines.
- **Retrieval-Augmented Generation (RAG)** over medical guidelines (NCCN, AGO) using Qdrant and BGE-M3 embeddings.
- **Structured clinical reasoning** generated by Qwen2.5-7B-Instruct via Ollama, following a Chain-of-Thought prompt.
- **Structured clinical report** with observations, conclusion, confidence score, original and annotated images.
- **Interactive web interface** with dashboard, upload, real-time progress, results viewer, history, chatbot, and PDF export.
- **Full multi-agent orchestration** with LangGraph.

## Architecture

The system is organized into four layers:

1. **Frontend (React + TypeScript)** — user interface, real-time updates via WebSocket.
2. **API Gateway (FastAPI)** — REST endpoints and WebSocket streaming.
3. **Orchestrator (LangGraph)** — coordinates the five specialized agents.
4. **AI Agents** — Vision, RAG, Reasoning, Report.
5. **Services & Databases** — PostgreSQL (persistence), Qdrant (vector search), Ollama (LLM runtime).

```
User
  │
  ▼
Frontend (React) ──► FastAPI (REST + WebSocket)
                         │
                         ▼
                 LangGraph Orchestrator
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
   Vision Agent     RAG Agent      Reasoning Agent
   (YOLO + Swin)   (Qdrant/BGE-M3)   (Qwen2.5-7B)
        │                │                │
        └────────────────┼────────────────┘
                         ▼
                  Report Agent
                         │
                         ▼
          PostgreSQL + Annotated Images
```

## Getting Started

### Prerequisites

- **Python 3.12+**
- **Node.js 18+** and **npm**
- **Docker** and **Docker Compose**
- **Ollama** installed and running ([ollama.com](https://ollama.com))
- **NVIDIA GPU** (recommended) with at least **8 GB VRAM**
- **PostgreSQL 15+** (or via Docker)
- **Qdrant** (or via Docker)

### Backend Setup

1. Clone the repository:

```bash
git clone https://github.com/YOUR_USERNAME/MediAI.git
cd MediAI/backend
```

2. Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate      # On Windows: .venv\Scripts\activate
```

3. Install dependencies:

```bash
pip install -r requirements.txt
```

4. Copy and edit the environment file:

```bash
cp .env.example .env
# Edit .env with your DB credentials, Qdrant host, Ollama host, etc.
```

5. Pull the LLM via Ollama:

```bash
ollama pull qwen2.5:7b-instruct
```

6. Index the medical guidelines into Qdrant (first run only):

```bash
python -m app.rag.indexer
```

7. Start the backend:

```bash
uvicorn app.main:app --reload --port 8001
```

The API will be available at `http://localhost:8001`, and the interactive Swagger docs at `http://localhost:8001/docs`.

### Frontend Setup

1. Navigate to the frontend folder:

```bash
cd ../frontend
```

2. Install dependencies:

```bash
npm install
```

3. Configure the API URL in `.env`:

```env
VITE_API_URL=http://localhost:8001/api/v1
VITE_WS_URL=ws://localhost:8001/ws
```

4. Start the development server:

```bash
npm run dev
```

The frontend will be available at `http://localhost:5173`.

### Docker Deployment

1. From the project root, build and start all services:

```bash
docker-compose up --build
```

Services started:
- `backend` (FastAPI) — `http://localhost:8001`
- `frontend` (React) — `http://localhost:5173`
- `postgres` — `localhost:5432`
- `qdrant` — `localhost:6333`
- `ollama` — `localhost:11434`

2. On the first run, pull the LLM and index the guidelines:

```bash
docker exec -it mediAI_ollama_1 ollama pull qwen2.5:7b-instruct
docker exec -it mediAI_backend_1 python -m app.rag.indexer
```

## Usage

### Submit a new analysis

1. Open the frontend at `http://localhost:5173`.
2. Fill in the patient's clinical data (age, history, risk factors).
3. Upload a mammogram (PNG / JPG / TIFF / DICOM).
4. Click **"Launch Analysis"**.

The system will:

1. Detect lesions with YOLO.
2. Generate elliptical masks and compute morphological metrics.
3. Classify each lesion with Swin Transformer.
4. Assign a BI-RADS category.
5. Retrieve relevant guidelines with RAG.
6. Generate a structured clinical reasoning with Qwen2.5.
7. Produce the final report with annotated images.

### Example API call

```bash
curl -X POST http://localhost:8001/api/v1/diagnosis \
  -F "patient_id=P-12345" \
  -F "age=55" \
  -F "history=Family history of breast cancer" \
  -F "risk_factors=Dense breast" \
  -F "mammo_file=@/path/to/mammo.png"
```

Response:

```json
{
  "task_id": "7d43b223-54d8-4142-bdfe-16b670871461"
}
```

Poll the result:

```bash
curl http://localhost:8001/api/v1/diagnosis/{task_id}/result
```

### Ask the chatbot

```bash
curl -X POST http://localhost:8001/api/v1/chat \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "7d43b223-...",
    "question": "Why is Lesion 1 classified as BI-RADS 4C?"
  }'
```

## Limitations

- **Residual LLM hallucinations**: despite a strict Chain-of-Thought prompt and RAG grounding, the model occasionally invents morphological details (< 5 % of reports).
- **Class imbalance in DMID**: 88 % of training patches are Normal, 7.7 % Benign and 4.3 % Malignant. This may bias the classifier toward the majority class.
- **Computation time**: the full pipeline runs in 30–50 s, mostly due to the LLM (25–45 s on a RTX 4060 with 8 GB VRAM, 4-bit quantization).
- **No clinical validation**: the system has not been validated by an independent radiologist. It is a research prototype and should not be used for clinical decisions without expert supervision.
